# GSS სავალუტო კურსები (Currency): ეროვნული ბანკის კურსების ელფოსტის შეტყობინებები, შეცდომები და გაფრთხილებები

## მიმღებები, სათაური, ფერები, წერილის ველები და მიწოდების სტატუსი

ოპერაციული წერილები იგზავნება გამგზავნიდან **`gss-noreply@gss.ge`** კონფიგურირებულ მიმღებებთან: თუ გარემოს ცვლადი **`NBG_RATES_EMAIL_TO`** საერთოდ არ არის გადაცემული (`undefined`), გამოიყენება ნაგულისხმევი მიმღები **`service@gss.ge`**. მიმღებების სია ცარიელი ხდება **მხოლოდ მაშინ**, როდესაც **`NBG_RATES_EMAIL_TO`** ცხადად არის მითითებული ცარიელი სტრიქონით, მხოლოდ ინტერვალებით ან მხოლოდ მძიმეებით (მაგალითად, `""`, `"   "`, `","`) - ასეთ შემთხვევაში წერილი **არ იგზავნება**, ბრუნდება `configuration_error` და შეცდომა ფიქსირდება სერვერის ლოგში.

- **რიგში ჩადგომა (`queued`) vs საფოსტო ყუთამდე მიწოდება:** წერილის გაგზავნა სრულდება ასინქრონულად `Mail.sendMail`-ის საშუალებით - სერვისი დაუყოვნებლივ აბრუნებს რიგში გადაცემის სტატუსს (`queued`), ხოლო პროვაიდერის პასუხი (მიღება ან შეცდომა) ლოგირდება ასინქრონულ callback-ში. ამიტომ რიგში ჩადგომა ან პროვაიდერის მიერ მოთხოვნის მიღება **თავისთავად არ ამტკიცებს** საბოლოო საფოსტო ყუთამდე მიწოდებას.
- **სათაურის ფორმატი:** `<hostname> - <სტატუსის სათაური>` (მაგალითად, `currency.gss.ge - ეროვნული ბანკის კურსები ჩამოიტვირთა`). დღის შემაჯამებელ `19:02` cutoff წერილს ყოველთვის აქვს ერთი ფიქსირებული სათაური: `<hostname> - გაფრთხილება: ეროვნული ბანკის კურსების განახლება ვერ დადასტურდა`.
- **HTML სათაურის (`<h2>`) ფერები და პოსტ-კომიტის გაფრთხილება:**
  - **შავი (`black`):** ახალი დადასტურებული ავტომატური იმპორტი (`imported`, ახლავს სრული `GEL` სავალუტო ცხრილი: `კოდი` / `რაოდენობა (ნომინალი)` / `კურსი (GEL)`). თუ ბაზაში შენახვა დადასტურდა, მაგრამ მის შემდეგ Redis კოორდინაციის განახლება ჩავარდა, `<h2>` სათაური რჩება **შავი** და მის ქვემოთ ემატება ცალკე **მარუნისფერი** აბზაცი: `გაფრთხილება: კურსების შენახვა დადასტურებულია, მაგრამ Redis-ის კოორდინაციის განახლება ვერ მოხერხდა: <დეტალი>`;
  - **მარუნისფერი (`maroon`):** უშუალო შეცდომები (ხელით ჩამოტვირთვის `5` შეცდომა და ავტომატური განრიგის `4` სემანტიკური/კონფლიქტის შეცდომა);
  - **მუქი ლურჯი (`navy`):** `19:02` დღის შემაჯამებელი `cutoff` გაფრთხილება (ფიქსირებული სათაურით და ბოლო შედეგის შესაბამისი ტექსტით).
- **წერილის ველები:** ველების სიაში იბეჭდება მხოლოდ **გაშვების რეჟიმი** (`ავტომატური (განრიგით)` ან `ხელით ჩამოტვირთვა - მომხმარებელი <id>`) და, არსებობისას, **კურსის მოქმედების თარიღი**. მცდელობის/მიღების/შენახვის დროითი ნიშნულები, მოსალოდნელი თარიღი, მომდევნო საწყისი დრო, ვალუტების რაოდენობა და წყაროს URL წერილში არ შედის. ტექნიკური გამონაკლისის არსებობისას ემატება `ტექნიკური დეტალი: <შეტყობინება>`, ხოლო სტრუქტურული შეუსაბამობებისას - ცხრილი **„აღმოჩენილი შეუსაბამობები“** (`ვალუტა`, `მიზეზი`, `მოსალოდნელი / მოდელში ან ბაზაში`, `ეროვნული ბანკიდან მიღებული`).

## ხელით ჩამოტვირთვა, ავტომატური განრიგი, `19:02` Cutoff და გამავალი წერილების ცხრილი

ქვემოთ აღწერილია მხოლოდ **რეალურად გამავალი** შეტყობინების შტოები (შაბლონის ამწყობში ზოგიერთი სტატუსისთვის არსებული ცალკეული შიდა სათაურები - მაგალითად, `already_present`, `not_yet_published`, `busy`, `database_error`, `redis_error` - დამოუკიდებელ გამავალ წერილებად არასდროს იგზავნება):

1. **ხელით ჩამოტვირთვა რედაქტირების ფორმაში (`POST /api/v2/currency-rates/fetch-nbg`):**
   - ოპერაციული მარუნისფერი წერილი იგზავნება **მხოლოდ `5` შეცდომაზე** (`model_mismatch`, `invalid_source`, `invalid_rate`, `date_anomaly`, `source_error`) **დედუპლიკაციის გარეშე** - ყოველი წარუმატებელი მცდელობა აგზავნის ერთ წერილს, რომლის ტექსტში მითითებულია: **„რედაქტირების ფორმა არ შევსებულა“**.
   - წარმატებული ხელით ჩამოტვირთვა მხოლოდ დრაფტს ავსებს და **წარმატების წერილს არ აგზავნის**.
   - ჩვეულებრივი HTTP `400` (არავალიდური თარიღი ან არა-`GEL` საბაზო ვალუტა), `401` (ავტორიზაციის არარსებობა) და `403` (GSS სერვისის მენეჯერის უფლების არარსებობა) პასუხები **ოპერაციულ წერილს არ აგზავნის**.
   - `already_present`, `not_yet_published`, `busy`, `storage_conflict`, `database_error` და `redis_error` სტატუსები ხელით ჩამოტვირთვისას საერთოდ **ვერ წარმოიქმნება** (ხელით ჩამოტვირთვა ბაზას და Redis-ს არ ეხება).
2. **ავტომატური განრიგი (`17:00-19:00`):**
   - `imported` აგზავნის შავ წარმატების წერილს (საჭიროებისას პოსტ-კომიტის მარუნისფერი Redis გაფრთხილებით);
   - `already_present` სრულად ჩუმია (წარმატების წერილი **არ იგზავნება**) და ბლოკავს დღის `cutoff` გაფრთხილებას;
   - **მხოლოდ `4` უშუალო შეცდომა** (`model_mismatch`, `invalid_rate`, `date_anomaly`, `storage_conflict`) აგზავნის მარუნისფერ წერილს და მხოლოდ მაშინ, როცა დადგენილია **`effectiveDate`** და წარმატებით ჩაიწერა **Redis `NX` `3`-დღიანი დედუპლიკაციის გასაღები** (`effectiveDate` + `status` + `issues` ანაბეჭდით);
   - ტექნიკური და დროებითი მდგომარეობები (`invalid_source`, `source_error`, `database_error`, `redis_error`, `not_yet_published`, `busy`) ფანჯრის განმავლობაში **ცალკე მარუნისფერ წერილებს არ აგზავნის** - ისინი ელოდებიან `19:02` cutoff-ს.
3. **დღის შემაჯამებელი `19:02` Cutoff (`navy`):**
   - დაგეგმილია თბილისის დროით **`19:02`**-ზე, მაგრამ თუ იმპორტის საკეტი ჯერ კიდევ აქტიურია, პროცესი ერთჯერადად ელოდება დარჩენილ საკეტს **მაქსიმუმ `120` წამი**.
   - Cutoff **ახალ HTTP მოთხოვნას არ აგზავნის** - ამოწმებს მხოლოდ Redis-ში შენახულ `:day:` და `:last-attempt:` მდგომარეობებს.
   - თუ Redis მიუწვდომელია (ან ორმაგი ხარვეზისას, როცა ადრინდელ წარმატებაზე `:day:` ჩაწერა ჩავარდა და შემდგომმა მცდელობამ შეცდომით გადააწერა `:last-attempt:`-ს), **`exactly-once` გარანტია არ არსებობს** და შესაძლებელია დუბლირებული ან დამატებითი cutoff წერილის გაგზავნა.
   - Cutoff წერილს ყოველთვის აქვს ფიქსირებული მუქი ლურჯი სათაური და შეუძლია ასახოს **`10` სტატუსი**: `model_mismatch`, `invalid_source`, `invalid_rate`, `date_anomaly`, `source_error`, `storage_conflict`, `database_error`, `redis_error`, `not_yet_published`, `busy`.

## შეცდომისა და შემაჯამებელი სტატუსების მიზეზები და რეაგირება

1. **`model_mismatch`** (უშუალო სათაური: `შეცდომა: ეროვნული ბანკის კურსების შეუსაბამობა ვალუტების მოდელთან`; cutoff-ზე - ფიქსირებული `navy` სათაური):
   - მიზეზები: `missing` (მოდელში აქტიური ვალუტა წყაროში არ არის), `unknown` (წყაროს ვალუტის კოდი მოდელში არ არის), `inactive` (აქტიურ უცხოურ ვალუტებს არ მიეკუთვნება), `duplicate` (კოდი მეორდება), `quantity` (რაოდენობა მოდელს არ ემთხვევა - მაგალითად, `JPY`: მოსალოდნელი `100`, მიღებული `1`).
   - რეაგირება: გადაამოწმეთ და გაასწორეთ ვალუტების მოდელი (ავტომატური გადათვლა არ სრულდება).
2. **`invalid_source`** (ხელით ჩამოტვირთვის უშუალო სათაური: `შეცდომა: ეროვნული ბანკის პასუხის ფორმატი არასწორია`; განრიგზე - მხოლოდ cutoff-ის ფიქსირებული `navy` სათაური):
   - მიზეზი: დაპარსული JSON პასუხის არასწორი სტრუქტურა, არავალიდური კალენდარული თარიღი, ცარიელი მასივი ან აუცილებელი ველების არარსებობა.
   - რეაგირება: შეამოწმეთ წყაროს ფორმატი; საჭიროებისას შეიყვანეთ კურსები ხელით რედაქტორიდან.
3. **`invalid_rate`** (უშუალო სათაური: `შეცდომა: ეროვნული ბანკის კურსის მნიშვნელობა არასწორია`; cutoff-ზე - ფიქსირებული `navy` სათაური):
