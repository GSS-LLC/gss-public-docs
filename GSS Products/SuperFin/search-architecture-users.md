# სუპერფინში ძებნის სრული სახელმძღვანელო

ეს სახელმძღვანელო განკუთვნილია სუპერფინის მომხმარებლისთვის. აქ აღწერილია, რა შეიძლება მოიძებნოს ანგარიშთა გეგმასა და საწყის ნაშთებში, ბრუნვაში, საბუთებსა და RS ანგარიშ-ფაქტურებში და როგორ უნდა ჩაიწეროს საძიებო ფრაზა.

## საძიებო ფრაზის საერთო წესები

### ველის მითითება

კონკრეტულ ველში საძებნელად ჯერ დაწერე ველის სახელი, შემდეგ ორწერტილი და მნიშვნელობა:

`სახელი: ბანკი`

`ანგარიში: 1410`

`RS თანხა: >=100.25`

გაფართოებული ძებნის ფანჯარა იმავე ფრაზას თავად აწყობს. ამიტომ ველის სახელების დამახსოვრება აუცილებელი არ არის, თუმცა უკვე აწყობილი ფრაზის ხელით შეცვლაც შეგიძლია.

### რამდენიმე სხვადასხვა პირობა

სხვადასხვა ველი ერთმანეთთან ერთდროულად მოქმედებს. შედეგი ყველა მითითებულ პირობას უნდა აკმაყოფილებდეს:

`სახელი: ბანკი არქივი: არა`

აქ მოიძებნება ანგარიში, რომლის სახელშიც არის „ბანკი“ და რომელიც არქივში არ არის.

სიტყვა `და` შეგიძლია ჩაწერო, თუმცა აუცილებელი არ არის:

`სახელი: ბანკი და არქივი: არა`

### რამდენიმე შესაძლო მნიშვნელობა ერთ ველში

თუ ერთი ველისთვის რამდენიმე შესაძლო მნიშვნელობა გინდა, გამოიყენე `ან`:

`იმპორტი: საქართველოს ბანკი ან თიბისი ბანკი`

ალტერნატივის გამყოფად `|` და `or`-იც მიიღება, თუმცა ქართულ ტექსტში ყველაზე გასაგებია `ან`. `ან` და `or` ცალკე გამყოფი სიტყვა უნდა იყოს; ორივე მხრიდან გამოტოვება დაუტოვე. მაგალითად, სწორია `ID: =66 ან 67`, ხოლო `ID: =66 ან67` ორ ალტერნატივად არ იკითხება.

იგივე შედეგს მიიღებ, თუ გაფართოებული ძებნის ფანჯარაში იმავე ველს მეორე ალტერნატივად დაამატებ.

ერთი ველის გამეორებაც ალტერნატივაა:

`სახელი: ბანკი სახელი: სალარო`

ეს ნიშნავს: სახელი შეიცავს „ბანკს“ ან „სალაროს“.

`ან` მხოლოდ ერთი ველის ალტერნატიულ მნიშვნელობებს ყოფს. სხვადასხვა ველებს შორის `ან` არ გამოიყენება:

`ანგარიში: 1410 ან მდგომარეობა: გასარკვევი`

ეს არ ნიშნავს „ან 1410, ან გასარკვევი“ და გამართულ ორ პირობადაც არ უნდა ჩაითვალოს. სხვადასხვა ველები `ან`-ის გარეშე ერთმანეთთან `და` წესით მოქმედებს:

`ანგარიში: 1410 მდგომარეობა: გასარკვევი`

თუ სხვადასხვა ველებს შორის `ან` გჭირდება, ძებნა ორჯერ გაუშვი.

### ბრჭყალები და უკუღმა დახრილი ხაზი (`\`)

შეგიძლია გამოიყენო როგორც ორმაგი (`"..."`), ისე ერთმაგი (`'...'`) ბრჭყალები. ბრჭყალები ერთ მთლიან მნიშვნელობას ან ალტერნატივას შემოსაზღვრავს. მათ შიგნით დაწერილი `ან`, `or`, `|`, `:`, ველის სახელი და მნიშვნელობის ბოლოს მდგომი `და` ან `and` გარე საძიებო ფრაზის გამყოფად აღარ იკითხება.

`თემა: "გადახდა ან ჩარიცხვა"`

აქ `გადახდა ან ჩარიცხვა` ერთი მნიშვნელობაა და არა ორი ალტერნატივა. ბრჭყალები ზუსტ ფრაზას არ ნიშნავს: ტექსტური ძებნა კვლავ თითოეულ სიტყვას ამოწმებს და მათ ზუსტ რიგს ან ერთმანეთის გვერდით ყოფნას არ მოითხოვს.

ბრჭყალები ასევე იცავს მნიშვნელობაში არსებულ ორწერტილს:

`თემა: "კოდი: 42"`

ჩადგმულ ძებნაში ბრჭყალები შიდა საძიებო ფრაზის საზღვარს აჩვენებს. რამდენიმე დონეზე სხვადასხვა სახის ბრჭყალის მონაცვლეობა ყველაზე მარტივია:

`ანგარიში: "1410 კონტაქტი: 'თანამდებობა: დირექტორი'"`

ორმაგ ბრჭყალებში `'` ჩვეულებრივი სიმბოლოა, ერთმაგ ბრჭყალებში კი — `"`. სიტყვის შიდა აპოსტროფიც, მაგალითად `O'Brien`, ბრჭყალის დასაწყისად არ ითვლება.

უკუღმა დახრილი ხაზი (`\`) escape-ის როლს მხოლოდ ბრჭყალებში ასრულებს და მხოლოდ მიმდინარე ბრჭყალსა და თვითონ `\`-ს აღწერს:

| სად | ჩანაწერი | მნიშვნელობაში რჩება |
| --- | --- | --- |
| `"..."` | `\"` | `"` |
| `"..."` | `""` | `"` |
| `"..."` | `\\` | `\` |
| `'...'` | `\'` | `'` |
| `'...'` | `''` | `'` |
| `'...'` | `\\` | `\` |

მაგალითად, `თემა: "Alpha \"Beta\""` ერთ მნიშვნელობად იკითხება: `Alpha "Beta"`. მიმდინარე ბრჭყალის გაორმაგებაც იგივე შედეგს იძლევა: `თემა: "Alpha ""Beta"""` და `თემა: 'O''Brien'`.

სხვა სპეციალური escape-ები არ არსებობს. `\n`, `\t`, `\:`, `\|`, `\0` და მეორე სახის ბრჭყალის წინ დაწერილი `\` ახალ ხაზად, tab-ად ან სხვა სპეციალურ სიმბოლოდ არ გარდაიქმნება; უკუღმა ხაზი უცვლელად რჩება.

ბრჭყალების გარეთ `\` escape არ არის. ანგარიშის სრულ ნომერში იგი იერარქიის გამყოფია, ამიტომ ჩვეულებრივი ფორმაა `1410\001` და არა `1410\\001`.

ჩადგმულ ბრჭყალებში ხელით დაწერილი `1410\001`-იც სწორია, რადგან `\0` სპეციალური escape არ არის. გაფართოებული ძებნის ფანჯრის მიერ აწყობილ ფრაზაში იგივე ნომერი შეიძლება `1410\\001`-ად გამოჩნდეს; ბრჭყალების შიგნით `\\` ერთ `\`-ად იკითხება.

გახსნილი ბრჭყალი აუცილებლად უნდა დაიხუროს და მთელ ერთ მნიშვნელობას უნდა მოიცავდეს. სწორია `თემა: "Alpha Beta" შესრულებული: კი`, ხოლო `თემა: "Alpha" Beta` გამართული ერთი მნიშვნელობა არ არის. გაფართოებული ძებნის ფანჯარა საჭირო ბრჭყალებსა და escape-ებს ავტომატურად ამატებს.

### ტექსტის ძებნა

ტექსტი დიდი და პატარა ასოების განსხვავების გარეშე იძებნება. სიტყვის დასაწყისიც საკმარისია:

`სახელი: ბანკ`

შეიძლება იპოვოს „ბანკი“, „ბანკის“, „ბანკები“ და სხვა სიტყვები, რომლებიც „ბანკ“-ით იწყება. „საბანკო“ ამ მაგალითით არ მოიძებნება, რადგან „ბანკ“ სიტყვის დასაწყისში არ არის.

თუ ერთ მნიშვნელობაში რამდენიმე სიტყვაა, ყველა სიტყვა უნდა მოიძებნოს:

`თემა: მომსახურება აგვისტო`

ბრჭყალები ზუსტ წინადადებას არ ნიშნავს: ისინი მნიშვნელობას აჯგუფებს, ხოლო ჩადგმულ ძებნაში შიდა ფრაზის საზღვარსაც აჩვენებს.

ერთსიმბოლოიანი ტექსტის ქცევა ძებნის ნაწილზეა დამოკიდებული:

| სად ეძებ | რას აკეთებს ერთი სიმბოლო |
| --- | --- |
| ანგარიშთა გეგმაში, საწყის ნაშთებსა და ბრუნვაში ანგარიშის ტექსტურ ველებში | გრძელი სიტყვის დასაწყისსაც პოულობს; მაგალითად `ბ` შეიძლება „ბანკს“ დაემთხვეს |
| საბუთის პირდაპირ ტექსტურ ველებში, გატარების ვალუტებში, RS ანგარიშ-ფაქტურებსა და SuperFin-იდან ჩადგმულ კონტაქტის პირობებში | მხოლოდ ცალკე ერთსიმბოლოიან სიტყვას შეიძლება დაემთხვეს; `დ` „დირექტორს“ ვერ იპოვის, ამიტომ გამოიყენე სულ მცირე `დი` |
| დამოუკიდებელ Contacts გვერდზე | ტექსტური ძებნისთვის სულ მცირე ორი სიმბოლოა საჭირო; დეტალები Contacts-ის სახელმძღვანელოშია |

ტექსტურ ველებში მძიმე, წერტილი, დეფისი, `/`, `\`, `_` და სხვა სასვენი ან სპეციალური ნიშნები, როგორც წესი, სიტყვების გამყოფებად მუშავდება. მაგალითად, `ნომერი: DOC-120` ეძებს `DOC`-სა და `120`-ს და არ ამოწმებს, რომ მათ შორის აუცილებლად დეფისი წერია. ანგარიშის სრული ნომერი გამონაკლისია: იქ `\` იერარქიის გამყოფია და თავდაპირველი სრული ნომრის დასაწყისიც დამატებით მოწმდება.

### რიცხვების შედარება

რიცხვით ველებში შეგიძლია გამოიყენო:

| ჩანაწერი | მნიშვნელობა |
| --- | --- |
| `=100` | ზუსტად 100 |
| `!=100` ან `<>100` | 100-ის გარდა |
| `>100` | 100-ზე მეტი |
| `>=100` | 100-ის ტოლი ან მეტი |
| `<100` | 100-ზე ნაკლები |
| `<=100` | 100-ის ტოლი ან ნაკლები |

ერთი მნიშვნელობის შიგნით რამდენიმე შედარება დიაპაზონს ქმნის:

`თანხა: >=100 <200`

ეს ნიშნავს 100-ის ჩათვლით და 200-მდე თანხას.

ალტერნატიული დიაპაზონებისთვის გამოიყენე `ან`:

`თანხა: <10 ან >=100`

ბაზის პირდაპირ რიცხვით ველში, მაგალითად `ID`-ში, ოპერატორის გარეშე დაწერილი რიცხვი ზუსტ ტოლობად იკითხება. მაგალითად:

`ID: =66 ან 67`

ეს ნიშნავს `ID = 66`-ს ან `ID = 67`-ს და `ID: =66 ან =67`-ის ეკვივალენტია. `ან` ცალკე გამყოფი სიტყვა უნდა იყოს და ორივე მხრიდან გამოტოვებით გამოყავი. `ID: =66 ან67` ID-ის რიცხვით პირობად აღარ იკითხება: მთელი ჩანაწერი თავისუფალ ტექსტად რჩება და `66`/`67` ID-ების ალტერნატიულ ფილტრს არ ქმნის.

გამონაკლისია ანგარიშთა გეგმისა და ბრუნვის უკვე დათვლადი თანხობრივი ველები: `ნაშთი`, `თანხა`, `დებეტი`, `კრედიტი`, `საწყისი`, `ბოლო` და `ბრუნვა`. მთავარ საძიებო ველში ხელით ჩაწერისას მათ რიცხვს ოპერატორი უშუალოდ უნდა მიეწეროს: `ნაშთი: =100`, `დებეტი: >=100`; არა `ნაშთი: 100` ან `დებეტი: >= 100`. გაფართოებული ძებნის ფანჯარა უბრალოდ შეყვანილ `100`-ს ავტომატურად `=100`-ად ფორმებს.

- უბრალოდ `100` თანხას არ ეძებს; გამოიყენე `=100`, `RS თანხა: 100` ან `RS დღგ: 100`.
